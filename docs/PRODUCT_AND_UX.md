# Product And UX

Daimon は「投稿SNS」ではなく、「観点(POV)を通じて他人の感性構造に触れる場所」です。

プロダクトの核はこれです。

> 同じものを見て、違う感じ方をしている人と、軽く出会う。

既存SNSは、似ている人、フォローしている人、反応が多い投稿を中心にネットワークを作ります。Daimon はそれだけではなく、「同じ観点を見ているが、感じ方が違う人」をつなぎます。

これは debate arena ではありません。勝ち負けではなく、相手の理由を聞くための小さな入口です。

## Surface と Substrate

Daimon は、表面を軽く、地下を深くします。

### Surface

ユーザーが触る表面は、できるだけ少ない動作にします。

```text
この観点で見ると？

なるほど
気になる
ちがうかも

一言理由は任意
```

ラベルは今後調整してよいですが、入口は1系統の3択に絞ります。`grade A/B/C`、`stance support/question/oppose/note`、`confidence` などを全部表に出すと、理論は深くても操作が重くなります。

### Substrate

地下では多くのことをします。

- 投稿本文をembeddingする。
- ユーザーの投稿と保存からsense centroidを作る。
- 人が選んだPOVを強いシグナルとして扱う。
- POVコメントを観点単位に蓄積する。
- 同じPOVで違うleanを持つ人を探す。
- 近い投稿だけでなく、共通POVを持つ遠い投稿を混ぜる。
- POV同士の類似・隣接・緊張関係をread modelにする。

この複雑さは、ユーザーに背負わせず、システム側に沈めます。

## POVコメント

普通のコメント:

```text
この投稿について話す。
```

POVコメント:

```text
この観点で見るとどうかを話す。
```

この差がDaimonの中核です。投稿コメントは投稿に閉じます。POVコメントは、投稿をまたいで観点に蓄積されます。

たとえば「テンポがよい」というPOVに対するコメントは、特定の投稿1件だけでなく、「テンポという観点をどう感じるか」の部屋になります。

## New Network For Human

Daimon の network は、フォローグラフだけではありません。

既存SNS:

```text
似ている人
知っている人
人気の人
```

Daimon:

```text
同じ観点を見ている人
同じ観点で違う感じ方をしている人
自分の感性から少し遠いが、共通の軸を持つ人
```

人followは残します。ただし、アプリの背骨は人followだけにしません。

- 人は信頼と継続性の手がかり。
- POVは探索と理解の地図。
- 投稿は、その人の感性が現れた断片。

## 同軸異見カード

最初に作るべきhero体験は、巨大なグラフではなく1枚のカードです。

```text
同じ観点で、少し違う感じ方

@someone は「テンポがよい」で、あなたと違う反応をしています。
理由: 中盤の間があるから、むしろ余韻として効いていた。

理由を読む
この観点を開く
```

重要なのは、最大対立を出さないことです。怒りを最大化する相手ではなく、「同じ軸に立っていて、理由を聞く価値がある相手」を出します。

選抜の考え方:

```text
same_pov
+ different_lean
+ short_reason_exists
+ recent_activity
+ quality_signal
+ not_blocked_or_muted
- hostility_risk
```

MVPでは完全なMLでなくてよいです。既存のPOV、POVコメント、保存、like、created_atだけで十分に試せます。

## 探索ビュー

グラフ探索は面白いですが、最初から「全部の関係を見せる巨大ネットワーク」にすると重くなります。Daimonに必要なのは、分析ツールではなく、感性の地図です。

内部データはグラフでも、UIは巨大なforce-directed graphではなく、`sense-distance` を歩ける探索空間にします。

```text
近い: 共感しやすい、居心地がいい
少し遠い: 新しいが理解できる
遠いが同じ軸: 同軸異見、bridge zone
```

探索の快感は、情報の匂いを辿って「見つける」ことにあります。Daimonでは、数字や通知で引っ張るのではなく、観点から観点へ進む感覚を報酬にします。

### 目的

- あるPOVから関連投稿へ進む。
- そのPOVに強いユーザーへ進む。
- 似たPOV、隣接するPOV、反対/緊張関係のPOVへ進む。
- 同じ観点で違う感じ方をしている人を見つける。
- 自分の興味がどの方向に広がったかを感じる。

### 玄関ではなく第二モード

最初の玄関は、1ジェスチャーです。

```text
POVに反応する
↓
同軸異見カードが1枚返る
```

探索ビューは、その後の第二モードです。

```text
今日は少し彷徨いたい
この観点の周辺を見たい
自分と遠いが同じ軸の人を見たい
```

空っぽの探索空間はつらいので、密度ができてから入れます。

### MVPの形

最初はPOVページに `探索` タブを置きます。

```text
中心: 現在のPOV
1 hop: 関連投稿、最近コメントしたユーザー、似たPOV
2 hop: その投稿についている別POV、同軸異見カード
```

上限:

- 初期表示は30ノード程度。
- 最大でも80ノード程度。
- 1-2 hopまで。
- 3Dではなく2D。
- グローバル全体図ではなく、現在地中心のlocal map。
- レイアウトはバネ図より、近い/遠いが読めるsense mapを優先する。

### ノード

| Node | 意味 | 表示 |
| --- | --- | --- |
| POV | 観点 | 短いチップ、中心ノード |
| Post | 投稿 | 小さな本文断片 |
| User | 人 | avatar/username |
| Assertion | この投稿をこのPOVで見た主張 | 3択のlean badge |
| Comment | POVコメント | 小さな点、必要時だけ展開 |

MVPでは `POV / Post / User` の3種類だけで始めてよいです。`Assertion` は `post_pov_assertions` が入ってから増やします。

### エッジ

| Edge | 意味 |
| --- | --- |
| `post_has_pov` | 投稿にPOVが付いている |
| `user_posted` | ユーザーが投稿した |
| `user_commented_on_pov` | ユーザーがPOVコメントした |
| `user_saved_post` | ユーザーが保存した |
| `pov_similar_to_pov` | 意味的に近いPOV |
| `pov_adjacent_to_pov` | 一緒に現れやすいPOV |
| `same_axis_disagreement` | 同じPOVで反応が違う |

エッジの説明は、hoverやside panelで短く出します。常に線の意味を全部表示すると読めなくなります。

### UI

探索ビューはメインコンテンツを奪わないようにします。

- POVページの1タブとして置く。
- ノードクリックで右側/下側に詳細パネルを開く。
- 中心POVは固定し、周辺だけ動かす。
- ノード数を増やす操作は明示的な「もう少し広げる」にする。
- レイアウトが落ち着くまでローディングを短く見せる。
- mobileではグラフを無理に広げず、横スクロールかカード列に変換する。
- `near / bridge / far` の領域が直感でわかるようにする。
- 線の多さより、次に進みたくなる `scent` を優先する。

### Scent

探索ビューで重要なのは、線の正確さより「次に開く理由」です。これを情報の匂いとして出します。

例:

```text
このPOVに近い
最近コメントが増えている
あなたの保存から近い
同じ観点で違う感じ方
この投稿からよく一緒に出る
```

ユーザーは抽象グラフを解読したいわけではありません。次にどこへ行くと面白そうかを知りたいだけです。

## 人間の本能的報酬とUI

ここでいう報酬UIは、依存を作るための仕掛けではありません。Daimonが使うべきなのは、内発的報酬です。

### 2種類の報酬

報酬UIには、Daimonが使うべきものと拒否すべきものがあります。

使う:

- seeking
- foraging
- 自己開示
- 発見
- closure
- reciprocity

拒否する:

- variable-ratio reward
- 無限スクロール
- streak義務
- 通知でのFOMO
- 数字による地位化
- 怒りの増幅

線引きはシンプルです。

```text
見つける / 繋がる / 分かる で満たされる報酬は使う。
満たされないよう設計された報酬は使わない。
```

### 使う報酬

#### 1. 探索の報酬

人は「次に何があるか」を探すこと自体に快感を感じます。

Daimonでは、無限スクロールではなく、観点から観点へ進む探索として使います。

UI:

- `次に開く観点`
- `この観点に近い`
- `この観点と少し緊張している`
- `同じ観点で別の感じ方`

#### 2. 自己開示の報酬

自分の感じ方を短く言語化すること自体が報酬になります。

UI:

- 3択 + 任意の一言。
- 長文を書く前に、まず立ち位置だけ置ける。
- 一言を書いた人だけ、相手の一言が少し開くようなreciprocityも検討できる。

#### 3. 発見の報酬

「自分と違うが、わかるかもしれない」という発見は強いです。

UI:

- 同軸異見カード。
- `あなたと違う` ではなく `同じ観点で少し違う` と言う。
- 相手の理由を先に出し、人格評価にしない。

#### 4. 収集の報酬

保存/クリップは、あとで読むだけでなく、自分の感性地図を作る行為です。

UI:

- 投稿保存。
- 保存した投稿から `あなたの最近の観点` を作る。
- 保存数を競わせず、自分の地図が育つ感覚にする。

#### 5. 所属の報酬

人は「自分が属している」と感じたい。ただし、Daimonでは陣営化を避けます。

UI:

- `この人たちは同じ観点を見ている`
- `この部屋で最近話されている`
- `あなたと遠い人も、この観点には反応している`

「敵味方」ではなく「同じ問いを見ている人」に寄せます。

#### 6. 成長の報酬

連続ログインやランキングではなく、感性の広がりを見せます。

UI:

- `最近開いた観点`
- `保存から広がった観点`
- `前は見ていなかった観点`
- `同じ観点で聞ける理由が増えた`

#### 7. Closureの報酬

Daimonで一番強い報酬は、最後に少し分かる瞬間です。

```text
自分が反応する
↓
同じPOVで違う感じ方の人が1人出る
↓
相手の短い理由を読む
↓
二人が同じだったところが1行で返る
```

例:

```text
違う感じ方でした。
でも二人とも「余韻が作品体験を左右する」と見ていました。
```

これはlike数より深い報酬です。勝ち負けではなく、重なりを見つける報酬です。そして終わりがあるため、無限に引きずりません。

### 使わない報酬

Daimonでは次を避けます。

- follower数を地位として大きく見せる。
- ユーザーをランキング化する。
- 反論や怒りを通知で煽る。
- streakで義務感を作る。
- グラフ中心性を公開して序列化する。
- 統計ダッシュボードでPOVを競技化する。
- 「あなたは間違っている」と見せる。

## Closure Beat

同軸異見カードは、出して終わりではありません。短い完了感まで設計します。

最小フロー:

1. ユーザーがPOVに3択で反応する。
2. 任意で一言理由を書く。
3. システムが同じPOVで違うleanの相手を1人出す。
4. ユーザーが相手の理由を読む。
5. システムが `違ったところ` と `同じだったところ` を短く返す。

UI例:

```text
違ったところ
あなた: 中盤の間が少し重い
相手: その間が余韻として効いている

同じだったところ
二人とも、テンポが体験の核だと見ている
```

ここで会話を終えても満足できるようにします。さらに議論したい人だけ、POVページへ進みます。

この設計にすると、Daimonは「もっと反応しろ」と押すSNSではなく、「少し分かった」で閉じられるSNSになります。

## POVページの強化方針

POVページは、Daimonの一番重要なページになります。

必要な要素:

- POVの説明
- 関連投稿
- 最近のPOVコメント
- 人気のPOVコメント
- そのPOVに強いユーザー
- 似たPOV
- 反対/隣接するPOV
- 同軸異見カード
- 探索タブ

ただし、初期表示で全部は出しません。

初期表示:

```text
POV title
短い説明
この観点で反応する 3択
同軸異見カード 1枚
最近のコメント
関連投稿
```

深掘り:

```text
探索タブ
関連POV
強いユーザー
過去の議論
```

## ランキングの方向

最終的なrankは、semantic similarityだけでは足りません。

```text
score =
  semantic_similarity
  + shared_pov_weight
  + pov_activity_recency
  + pov_comment_quality
  + user_affinity_by_pov
  + disagreement_but_same_axis_bonus
  + save_quality_signal
```

特に重要なのは、`disagreement_but_same_axis_bonus` です。

普通のSNSでは、違う意見は衝突になりやすいです。Daimonでは「見ている観点が同じ」という文脈を先に作ることで、違いを好奇心に変えます。

## FE性能方針

探索ビューは重くなりやすいので、最初から性能制約を設計に入れます。

- 探索APIは必要なノードだけ返す。
- 初期表示のノード数を固定する。
- layout計算は再レンダリングごとに走らせない。
- ノード/エッジcomponentはmemo化する。
- suggestion inputはdebounceする。
- 投稿カードは本文、ヘッダー、POV listを分割し、不要な更新を避ける。
- mobileではグラフよりカード探索を優先する。
- 画像や重いML結果を初期レンダリングに混ぜない。
- `hover` で十分な情報はmodalにしない。

探索ビューが主役になりすぎると、使う人が迷います。Daimonの主役は、あくまで観点と理由です。

## 最初に作るべきもの

1. POVページの初期表示を強化する。
2. 3択 + 任意一言のPOV反応を作る。
3. 同軸異見カードを1枚出す。
4. 保存をsense signalとして扱う。
5. POV中心のsense-distance探索タブを作る。

この順がよいです。最初から巨大グラフを作るより、まず「同じ観点で違う感じ方に出会う」体験を短く成立させます。
