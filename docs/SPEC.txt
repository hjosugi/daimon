================================================================================
DAIMON — 理論から導いた機能スペック (SPEC / 何を作るか)
================================================================================
最終更新: 2026-06
このドキュメント = 「何を作るか」。なぜ(研究60本) は CONCEPT_AND_RESEARCH.txt。
読み方: 各機能には必ず "← 理論" が付く。理論の無い機能は載せない。
大原則: 基盤は深く、表面は1ジェスチャー。迷ったら表面を削る(Tesler's Law)。


--------------------------------------------------------------------------------
0. 還元しきれない核 (the one thing) — これ1つを良くする裏方が全機能
--------------------------------------------------------------------------------
   「同じものを見て、違う感じ方をしてる人と、軽く出会う。」

   既存SNS = 似てる人 / 同意で繋ぐ(homophily)。
   daimon  = 同じ軸(POV)を見ていて、stance が違う人と繋ぐ。
   人にとっての価値 = perspective-getting(相手の視点を想像でなく実際に聞く)。
   ← Eyal, Steffel & Epley (2018) "Perspective mistaking": 想像(taking)は精度を
      下げ確信だけ上げる。「他人の心は口を通して出てくる」。


--------------------------------------------------------------------------------
1. 設計4法則 (全機能がこれに従う / 違反は作らない)
--------------------------------------------------------------------------------
L1 複雑さは沈める (Tesler's Law / 複雑さ保存則)
   複雑さは消えない。誰が背負うかだけ。daimon は vector・bridging・sense-distance・
   観点分解を全部 system 側に沈め、ユーザーには1動作だけ渡す。
   ← 検索窓1個の裏のPageRank、Community Notesの「役に立った?」1タップの裏のMF。

L2 報酬の線引き (本能的報酬には敵と味方がいる)
   使う = 「見つける/繋がる/分かる」で“満たされて終わる”報酬:
     SEEKING/採餌(Panksepp; Pirolli & Card; Bromberg-Martin & Hikosaka 2009=情報
     自体がドーパミン報酬), 好奇心ギャップの解消(Loewenstein), 自己開示(Tamir &
     Mitchell), closure/insight。
   拒否する = “満たされないよう設計された”報酬(variable-ratio スロットマシン):
     いいね数の地位化, 連続記録, 無限スクロール, 赤バッジ通知, FOMO。
     ← これは §1.1 が批判する engagement 最大化マシンそのもの。
   線引き: 「沼らせない」を明示的に設計し、それを差別化として売る。

L3 聞かせる、推測させない
   相手の理由は本人の言葉で開く。debate arena にしない。対決でなく招待。
   ← Epley (perspective-getting) / Habermas Machine(persuade でなく mediate)。

L4 統計でなく温度
   数字(A40/B3/総計43)を出さない。一行の vibe を出す
   (「だいたい共感寄り、でも最近"問い"が増えてる」)。
   ← ErogameScape との分岐点: あれは複雑さを表に出す。daimon は沈める(L1)。


--------------------------------------------------------------------------------
2. 表面 (SURFACE — 普通の人が触る全UI / 各機能 = 1理論)
--------------------------------------------------------------------------------
S1 リアクション1ジェスチャー  [玄関 / これ以上削れない最小単位]
   ある観点に「なるほど / うーん / それは違う」を1タップ＋一言(任意)。投稿不要。
   ← Pol.is(=意見空間への1票) / Tamir & Mitchell(一言自体が報酬→入口が軽い)

S2 同軸異見カード  [HERO / 最初に作る]
   返るのは統計でなく “人1人＋理由1行”:「○○さん、同じ観点で逆。なぜなら—[一言]」。
   ランダムでも最大対立でもなく、同じ軸・逆の傾きを bridging で1人選抜。
   ← bridging-based ranking(Birdwatch/Habermas) / Epley / Brewer 最適弁別性

S3 closure（重なり提示）  [思想の証明 / これが“沼SNS”との違いを一発で見せる]
   逆の人と最小やりとり → 最後に「二人が同じだったのはここ」を差し出す。
   報酬 = insight/完了。終わりがあるからスロットにならない(L2)。
   ← Habermas Machine の payload は「対立の提示」でなく「overlap の提示」

S4 軸の温度（1行）   ← L4 / room の空気

S5 explore 空間  [第2モード / Phase 2+]
   自分中心の点。近く=共感(居心地)、外へ漕ぐほど同軸異見(bridge zone)。
   sense-distance がそのまま歩ける空間。採餌本能が外へ引っ張り、bridging が
   「外=脅威」を「外=面白い」に変える。
   ※ force-directed ノードグラフにはしない(L1違反/規模破綻)。
   ← Pirolli & Card 情報採餌 / 情報の匂い(scent)

S6 観点フォロー（軸の購読）  [Phase 2+]
   home を「人の follow」でなく「追う軸＋self-sense に近い軸で今起きてること」に。
   人=コンテンツ、観点=地図。follow-graph を背骨にしない。
   ← Granovetter 弱い紐帯 / Pol.is


--------------------------------------------------------------------------------
3. 地下 (SUBSTRATE — 1行も見えない、でも全部効いてる)
--------------------------------------------------------------------------------
   - sense vector（stance で動的に動く / “軌跡の収束”で繋ぐ将来余地）
   - POV 分解（長文をバッチで複数観点へ deep-analyze）
   - bridging 選抜（同じ軸・逆の傾きを1人に絞る）
   - sense-distance 空間（S5 の土台）
   - 埋め込み: paraphrase-multilingual-MiniLM-L12-v2(384d) / Qdrant / Redis batch
   全て S1–S6 を良くするための裏方。表面には1つも出さない(L1)。


--------------------------------------------------------------------------------
4. 作らないもの (ANTI-FEATURES / なぜ作らないか付き)
--------------------------------------------------------------------------------
   × 統計ダッシュボード(A/B/C 露出)      → L1違反。複雑さを表に出す。
   × force-directed ノードグラフ        → L1違反/冷たい/規模破綻。S5で代替。
   × variable-ratio 系                  → L2違反。§1.1の批判対象を自分が実装する罠。
     (いいね数競争 / 連続記録 / 無限スクロール / FOMO通知)
   × grade(A/B/C) と stance 両系統をユーザーに暗記させる → 入口は lean 1系統3択のみ。
   × follow-graph を spine にする        → navigation は軸。人は残すが背骨にしない。


--------------------------------------------------------------------------------
5. 作る順 (PHASE) ＋ 正直な懸念
--------------------------------------------------------------------------------
P1  S2 同軸異見カード（既存 pov_likes / stance / POV データだけで動く。新table不要）
    ＋ S3 closure ビートを先に設計すると、demo が一番効く(思想がそのまま見える)。
P2  S5 explore 空間 / S6 観点フォロー（密度ができてから）。
P3  動的 sense（軌跡の収束で繋ぐ「時間的マッチ」）— 競合がほぼ居ない空き地。

懸念A  全部 density 依存の cold-start。同じ軸に人が薄いと bridging が発火しない。
       → fallback 必須: 「逆の人」が居ない軸では普通に共感を返す。
懸念B  人follow を spine から外すと「友達が居るから来る」引力が消える。
       → 純粋な軸ネットワークにはしない。人(account/post/bio)は残す。今の判断は正しい。
懸念C  盛った理論が「複雑を作る言い訳」になる罠。基盤が深いほど表面は1動作まで削る。
将来論点  bridging の「全視点を等重み」は公正と言えない。stake 比例の重み
          (proportionality) が要る。— 将来の設計課題。
